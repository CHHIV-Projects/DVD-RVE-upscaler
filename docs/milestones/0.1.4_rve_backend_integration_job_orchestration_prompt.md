# 13. Job State Machine

Use a small explicit state machine.

A suitable contract is:

```text
created
running
cancel_requested
cancelled
completed
failed
interrupted
```

Allowed normal transitions:

```text
created → running

running → completed
running → failed
running → cancel_requested

cancel_requested → cancelled
cancel_requested → failed
```

Service-restart reconciliation may produce:

```text
running → interrupted
cancel_requested → interrupted
```

Do not transition a terminal job back to running.

Do not silently convert failure/interruption into success.

# 17. Process Ownership

Launch the RVE process as a new process session/group so cancellation can target only that job's process tree.

On Linux, a suitable approach is:

```text
start_new_session=True
```

or an equivalent safe mechanism.

Persist:

```text
pid
pgid
```

while active.

The application must never use:

```text
pkill python
killall python
pkill ffmpeg
killall ffmpeg
pkill rve
```

or any similarly broad command.

Only the specific job-owned process group may be signaled.

# 18. Safe Cancellation

Provide explicit cancellation of the active RVE job.

The intended sequence is:

```text
Product Owner requests cancellation
→ state = cancel_requested
→ verify this service currently owns the live process handle/group
→ SIGTERM only the job-owned process group
→ bounded grace period
→ if still alive, SIGKILL only that same verified process group
→ wait/reap process
→ state = cancelled
```

Choose and document a reasonable grace period.

Do not signal a PID/PGID merely because a stale database row contains it.

If the application cannot prove live ownership of the process:

```text
do not kill it blindly
```

Return an interrupted/operator-review state instead.

Cancellation must not:

```text
delete prepared input
delete source media
publish partial output
mark the job completed
```

Retain local job/log evidence.
