# 1. Goal

Implement the first safe media-facing workflow:

```text
approved read-only DVD source root
→ discover candidate original MKV files
→ select one candidate
→ inspect media metadata with ffprobe
→ perform bounded distributed idet content sampling
→ produce a conservative media-analysis result
→ display the evidence/result through the existing LAN browser application
```

This milestone establishes the **discovery and analysis contract**.

It does **not** prepare, transform, enhance, publish, rename, move, or delete media.

At the end of this milestone the Product Owner should be able to open the existing browser application, view DVD-source candidates discovered from the approved read-only NAS root, select an original MKV, run a bounded analysis, and see a friendly summary of:

```text
file identity
duration
video geometry
SAR / DAR
frame rate
field-order metadata
audio streams
subtitle streams
chapters
distributed idet evidence
content classification
final conservative classification
review-required reason when applicable
```

## 6.1 Candidate files

For v1 discovery, candidate media files are:

```text

with .mkv extension
under /mnt/nas/movies/DVD
```

Discovery may recurse through movie subdirectories.

Do not follow symlinks.

Skip:

- symlink files;
- symlink directories;
- non-MKV files;
- inaccessible entries;
- directories outside the approved root.

## 6.2 Enhanced-file exclusion

The default candidate list should represent likely **original DVD sources**, not already-enhanced RVE versions.

```text

```

# 9. Geometry Evidence

The analysis result should compute, but **not execute**, the deterministic square-pixel preparation geometry adopted in 0.1.0.

Use:

```text
display_width = round(coded_width * sar_num / sar_den)
display_height = coded_height

prepared_width = nearest_even(display_width)
prepared_height = nearest_even(display_height)
```

Expected examples include:

```text
720x480 widescreen anamorphic
→ approximately 854x480 square pixel

720x480 4:3
→ approximately 640x480 square pixel
```

Display the proposed square-pixel geometry as **analysis evidence only**.

Do not create a prepared file.

# 10. SAR / DAR Consistency Check

Use SAR as the primary source for square-pixel derivation.

Use DAR as a cross-check.

If SAR is:

```text
missing
invalid
zero
unparseable
```

do not guess.

If calculated display ratio and reported DAR disagree materially, classify the geometry evidence as review-required.

Use the 0.1.0 v1 tolerance:

```text
greater than approximately 2% ratio disagreement
```

for a standard DVD ratio consistency check.

Do not silently substitute a hard-coded 16:9 assumption.

# 11. Distributed idet Content Sampling

Implement bounded content sampling using FFmpeg's:

```text
idet
```

filter.

The purpose is to examine actual decoded frame behavior rather than trusting `field_order` metadata alone.

Do not decode the full movie.

---

## 11.1 Sampling positions

For normal feature-length media, sample approximately:

```text
20%
50%
80%
```

of the total duration.

Avoid relying on a single sample.

For unusually short files, safely clamp the sampling positions so they remain within valid duration.

If duration is missing or invalid, return review-required/unsupported rather than guessing sampling locations.

---

## 11.2 Frames per sample

Use a bounded default of approximately:

```text
1000 decoded video frames per sample
```

unless current implementation evidence establishes that a slightly smaller bounded value is materially safer while preserving useful classification evidence.

Do not substantially increase sampling without Product Owner approval.

The target is representative evidence without performing a near-full movie decode.

---

## 11.3 Command behavior

Conceptually the command may resemble:

```text
ffmpeg
-nostdin
-ss <sample-time>
-i <approved-source>
-map 0:v:0
-vf idet
-frames:v <bounded-count>
-an
-sn
-dn
-f null
-
```

Construct arguments programmatically.

Do not use a shell command assembled from user input.

Capture stderr because `idet` reports its statistics there.

Add a bounded timeout so a broken media file cannot indefinitely hold a web request.

Choose a sensible timeout based on the actual local runtime, and document it in the closeout.


# 13. Classification Contract

The project requires these final classifications:

```text
progressive
interlaced_tff
interlaced_bff
telecine_suspected
ambiguous
unsupported
```

Implement a **conservative** classifier.

False certainty is worse than `ambiguous`.

---

## 13.1 Per-sample ratios

For each usable sample define:

```text
determined = TFF + BFF + Progressive
```

If there are too few determined frames to form meaningful evidence, that sample is insufficient.

Calculate:

```text
progressive_ratio
tff_ratio
bff_ratio
repeated_field_ratio
```

using parsed idet counts.

Keep the raw counts as part of the result.

---

## 13.2 Clear progressive content

A `content_classification` may be `progressive` only when the distributed samples consistently show strong progressive evidence.

Use a conservative starting rule approximately equivalent to:

```text
all usable samples:
progressive_ratio >= 95%
and
neither TFF nor BFF materially dominates
and
no strong repeated-field / cadence signal
```

Do not treat metadata alone as proof of progressive content.

---

## 13.3 Clear TFF interlace

A `content_classification` may be `interlaced_tff` only when distributed samples consistently show strong TFF evidence.

Use a conservative starting rule approximately equivalent to:

```text
all usable samples:
TFF ratio >= 90%
Progressive evidence is minor
BFF does not materially conflict
no strong telecine signal
```

---

## 13.4 Clear BFF interlace

Likewise, `interlaced_bff` requires consistent strong BFF evidence across usable samples.

Do not select field parity from metadata alone.

---

## 13.5 Telecine suspected

Use:

```text
telecine_suspected
```

when repeated-field/cadence evidence is materially present or the detected pattern looks cadence-sensitive rather than like ordinary fixed-parity interlace.

Do not attempt inverse telecine in this milestone.

If the evidence is not strong enough to distinguish telecine from mixed/uncertain material, return:

```text
ambiguous
```

instead.

---

## 13.6 Ambiguous

Return:

```text
ambiguous
```

when, for example:

- distributed samples disagree;
- evidence is materially mixed;
- too few frames are determined;
- TFF/BFF dominance changes between samples;
- metadata materially contradicts otherwise-clear content evidence;
- SAR/DAR geometry evidence is inconsistent;
- telecine is plausible but not confidently identified;
- evidence is otherwise insufficient for a safe automatic transform decision.

This is intentional.

`ambiguous` means:

```text
Product Owner review required before any future preparation transform
```

---

## 13.7 Unsupported

Return:

```text
unsupported
```

when analysis cannot safely proceed, for example:

- no usable video stream;
- source cannot be probed;
- duration required for sampling cannot be established;
- required metadata is structurally unusable;
- FFmpeg/ffprobe fails in a way that prevents meaningful analysis.

Do not convert an execution failure into a guessed media classification.
