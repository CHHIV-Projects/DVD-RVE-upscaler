# 2. Product UX Vision

The controlling Product Owner workflow is:

```text
1. User rips DVD outside this application
   ↓
2. Original MKV exists beneath one of the configured Original DVD Source Locations
   ↓
3. User launches DVD RVE Upscaler
   ↓
4. User searches for and selects the DVD
   ↓
5. User selects the intended Finished Movie Destination
   ↓
6. Application analyzes the source
   ↓
7. User reviews/resolves preparation only if needed
   ↓
8. User prepares DVD
   ↓
9. User reviews minimal RVE enhancement settings/profile
   ↓
10. User starts RVE enhancement
    ↓
11. Browser shows progress + CPU/GPU status
    ↓
12. Enhancement completes and validates
    ↓
13. Application shows the intended destination and a clear completed/ready-to-publish state
```

Actual NAS publication is **NOT** part of 0.1.5.

Milestone 0.1.6 will implement final remux/validation/publication.

# 6. Critical UX Change — Configurable Library Locations

The current hard-coded source:

```text
/mnt/nas/movies/DVD
```

was an appropriate development safety boundary.

It is **not** the permanent product model.

The Product Owner may keep original DVD rips in multiple places and may reorganize them gradually after enhancement.

Example transitional state:

```text
\\HENDERSON-NAS\Movies\DVD
```

may contain recent/unprocessed originals while:

```text
\\HENDERSON-NAS\Movies\DVD Originals
```

may eventually contain archived originals.

The application must therefore support **multiple approved Original DVD Source Locations**.

---

# 7. Library Location Roles

Introduce two logical location roles:

```text
ORIGINAL_SOURCE

FINISHED_DESTINATION
```

These roles are intentionally distinct.

## ORIGINAL_SOURCE

Places where original DVD MKVs may be discovered and selected.

There may be multiple active source locations.

## FINISHED_DESTINATION

Places where completed upscaled movies are intended to be published.

There may eventually be multiple destinations.

0.1.5 allows destination configuration/selection but performs **no NAS write**.

# 10. Trusted Location Boundary

Do not turn the browser into an arbitrary server filesystem browser.

For this milestone, configured NAS locations must resolve beneath the existing trusted mounted NAS Movies hierarchy:

```text
/mnt/nas/movies
```

The current mount remains read-only.

A location configuration must reject:

```text
/
..
path traversal
symlink escape
arbitrary /home paths
arbitrary /etc paths
arbitrary other server filesystems
```

If supporting a location outside the currently trusted NAS mount would require a new NAS share/mount or system configuration:

```text
do not add it in 0.1.5
```

The registry/data model should not make multiple future mounted NAS roots architecturally impossible, but do not add new mounts now.
