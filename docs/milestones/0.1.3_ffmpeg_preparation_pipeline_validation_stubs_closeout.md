## 4. Preparation Eligibility Contract

Discovery remains unchanged and may show readable analysis candidates that are not transformable. Preparation applies a separate conservative predicate.

An eligible source must:

- pass the accepted relative-path containment validator;
- exist beneath the approved source root;
- be a readable regular `.mkv`;
- contain no symlink component;
- reside on the verified read-only source mount; and
- contain no recognized enhancement marker in its filename stem.

Case-insensitive enhancement markers:

- standalone `RVE`;
- standalone `Nomos` or `Nomos8k`;
- the phrase `Medium 2x`, allowing normal spaces, dots, underscores, or hyphens.

Token boundaries avoid false positives in ordinary words such as `Harvey`.

## 5. Analysis-to-Preparation Decision Contract

Automatic proposals:

```text
final progressive     -> progressive
final interlaced_tff  -> deinterlace_tff
final interlaced_bff  -> deinterlace_bff
```

Unambiguous analysis rejects a conflicting selected mode. `telecine_suspected`, `unsupported`, and other unmapped outcomes are blocked.

Ambiguous or `review_required` analysis has no automatic proposal. It requires an explicit Product Owner choice:

- Treat as progressive;
- Deinterlace TFF;
- Deinterlace BFF; or
- Do not prepare.

The plan records content/final analysis classifications, review reasons, selected decision, and whether it is an explicit override.

## 7. Preparation Plan Contract

The persisted local `plan.json` records:

- preparation ID;
- relative and internal absolute source identity;
- source size and modification time;
- content/final analysis classifications and review reasons;
- selected decision and override status;
- source and target geometry;
- deterministic filter;
- encoder/settings/pixel format/frame rate;
- audio/subtitle/chapter/metadata policies;
- source duration and stream evidence;
- work, partial, and final paths;
- free-space evidence;
- timeout; and
- diagnostic structured FFmpeg arguments.

The public plan omits internal source, temporary-output, modification-time, and raw-command fields. The browser shows the controlled source, decision, geometry, filter, encoder, stream policies, and final local destination before execution.

Execution reloads the server-owned plan and re-derives the filter from the approved decision and geometry. A stored plan whose filter, encoder, or pixel format does not match the locked contract is rejected.


## 10. Execution / Failure Contract

Execution is one synchronous preparation for one server-owned plan. The timeout is:

```text
21600 seconds (6 hours)
```

This is finite while allowing a full DVD preparation on the validated GPU-first path. If measured Product Owner execution proves synchronous operation impractical, the milestone must escalate rather than add 0.1.4 orchestration.

Safety behavior:

- structured argument list with no shell;
- `-nostdin`;
- `-n`, never unconditional `-y`;
- one atomic `execution.started` marker per preparation ID prevents duplicate/concurrent execution;
- FFmpeg writes only `prepared.partial.mkv`;
- non-zero exit, timeout, launch failure, missing/invalid output, WARNING, or FAIL never promotes;
- partial evidence remains in its unique directory;
- no automatic deletion;
- no broad process killing; and
- promotion uses a no-overwrite hard-link operation followed by partial unlink.

If safe promotion itself fails, the validated partial remains and the result is failure.

## 11. Validation Contract

The validator uses ffprobe and checks:

- file exists and is non-zero;
- ffprobe readability;
- H.264 codec;
- expected width and height;
- SAR `1:1`;
- progressive field order;
- `yuv420p`;
- frame rate within 0.1% of the plan;
- duration within `max(0.5 seconds, 0.5% of source duration)`;
- audio stream count and codec/channels/language metadata;
- subtitle stream count and codec/language metadata; and
- chapter-count equality.

Outcomes:

- `PASS`: all required and comparison checks pass; only this outcome promotes.
- `WARNING / REVIEW REQUIRED`: non-destructive stream metadata discrepancy; no promotion.
- `FAIL`: any required integrity failure; no promotion.

Audio/subtitle metadata discrepancies are warnings. File, video, duration, stream-count, and chapter failures are blocking failures.
