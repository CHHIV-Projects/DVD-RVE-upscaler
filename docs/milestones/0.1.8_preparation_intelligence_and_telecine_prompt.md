Objective
=========

Improve DVD preparation intelligence so the operator receives a concise, useful explanation of what the source appears to be and what preparation method is recommended.

Add safe executable handling for film-source DVDs that exhibit telecine / 3:2 pulldown.

The normal Product Owner workflow remains:

  Find DVD
      ->
  Analyze & Prepare
      ->
  Enhance
      ->
  Finalize
      ->
  Publish

0.1.8 changes the intelligence and preparation behavior inside Analyze & Prepare only.

It must not redesign the rest of the workflow.

Current established behavior
============================

The existing analysis system already uses:

- ffprobe metadata;
- multiple IDET samples;
- final multi-frame IDET detection;
- classifications such as:
  - progressive
  - interlaced_tff
  - interlaced_bff
  - telecine_suspected
  - ambiguous
  - unsupported

Existing preparation behavior includes:

Progressive:
  scale=W:H,setsar=1,setfield=prog

TFF interlaced:
  bwdif=mode=send_frame:parity=tff:deint=all,
  scale=W:H,setsar=1,setfield=prog

BFF interlaced:
  bwdif=mode=send_frame:parity=bff:deint=all,
  scale=W:H,setsar=1,setfield=prog

Preparation encoding remains the existing NVENC path:

  h264_nvenc
  preset p7
  rc vbr
  cq 16
  b:v 0
  yuv420p
  fps_mode passthrough

Do not change those established progressive/interlaced semantics except where explicitly required by this milestone.

Known real-world evidence
=========================

These examples informed the milestone and should be useful as regression/reference cases.

Kingpin:

- metadata suggested progressive;
- samples were overwhelmingly progressive;
- small isolated TFF counts occurred in one sample;
- practical recommendation: Treat as progressive.

Fast Times At Ridgemont High:

- metadata included top-field-first indication;
- samples were approximately:
  - 987 progressive / 0 TFF
  - 948 progressive / 54 TFF
  - 998 progressive / 0 TFF
- approximately 98% progressive overall;
- practical recommendation: Treat as progressive.

Miracle On 34th Street:

- existing classification: telecine_suspected;
- first and third samples were nearly/all progressive;
- middle sample contained substantial TFF and repeated-field evidence;
- approximately 20% repeated-field behavior was observed in the affected sample;
- metadata indicated TFF;
- current application blocked execution because telecine was not supported;
- this is the key use case for 0.1.8.

Do not hardcode these movie names or exact observed percentages into production logic.

3. Recommended treatment

  Recommended: Deinterlace as Bottom Field First.

  Recommended: Restore film cadence with inverse telecine.

  Unable to make a safe automatic recommendation.

4. Explanation

Provide a short human-readable reason for the recommendation.

Examples of the intended level:

   telecine."

Keep this concise in the normal UI.

Do not turn this milestone into a general technical-media inspector.

Part B — Classification behavior
================================

Review the existing classification thresholds and decision path only as much as required to support reliable recommendation and telecine execution.

Required principles:

1. Small isolated TFF/BFF counts must not automatically force genuinely progressive material into deinterlacing.

2. Consistently interlaced material must continue to resolve to TFF or BFF as appropriate.

3. Telecine classification must rely on meaningful cadence/repeated-field evidence rather than merely the presence of some interlaced frames.

4. Conflicting or insufficient evidence must remain ambiguous rather than being forced into an executable classification.

5. Preserve conservative failure behavior.

Do not broadly retune IDET heuristics without evidence from the existing implementation and tests.

If current thresholds cannot safely distinguish these cases with the data presently retained, STOP and report the smallest additional evidence/state required before changing semantics.

Part C — Telecine / IVTC execution
==================================

Add a proper preparation path for sources classified as executable telecine / film-source pulldown.

Intent:

  telecined film source
      ->
  inverse telecine / cadence restoration
      ->
  progressive frames
      ->
  existing geometry normalization
      ->
  existing NVENC preparation encode
      ->
  RVE

Do NOT simply send telecine material through ordinary BWDIF deinterlacing.

Use FFmpeg's established inverse-telecine facilities appropriate to the current source and pipeline.

The implementation should normally be based on a cadence-aware field-match plus decimation approach, such as:

  fieldmatch
      ->
  decimate

or the equivalent justified by the installed FFmpeg capabilities.

The coder must inspect the current FFmpeg environment and existing filter construction before locking the exact filter expression.

Required output properties after IVTC:

- progressive;
- square-pixel normalized using the existing geometry contract;
- existing prepared width/height contract preserved;
- compatible with the existing RVE profile;
- audio/subtitles/chapters handled consistently with current preparation behavior;
- no source mutation.

Frame-rate behavior
===================

For conventional NTSC film telecine, IVTC normally restores the underlying film cadence rather than retaining duplicated telecine frames.

Do not blindly force the old 30000/1001 frame rate after decimation if correct IVTC produces approximately 24000/1001 progressive output.

The implementation must:

1. determine the resulting expected frame rate from the actual IVTC operation;
2. retain that rate through preparation;
3. validate it appropriately;
4. avoid unnecessary duplicate-frame generation.

Do not change frame rate for ordinary progressive or ordinary interlaced preparation paths unless existing semantics already require it.

Duration / synchronization
==========================

Preserve normal movie duration and A/V synchronization within the existing validation tolerances.

IVTC removes duplicate video frames; it must not shorten the movie's real playback duration.

Validate that:

- video remains readable;
- audio remains synchronized;
- expected streams remain present;
- duration remains within the existing allowed tolerance;
- output is progressive;
- cadence/frame rate is appropriate.

Escalation protocol
===================

STOP and report before broadening scope if any of the following is discovered:

1. Reliable telecine detection cannot be achieved from the evidence currently retained.

2. Proper IVTC requires a significant redesign of the preparation model.

3. Correct IVTC frame-rate handling conflicts with downstream RVE assumptions.

4. Existing validation hardcodes 30000/1001 in a way that requires substantial architecture changes.

5. Audio/subtitle/chapter preservation cannot remain compatible with the existing preparation contract.

6. A database migration is required.

7. The installed FFmpeg lacks the required filters.

8. Safe implementation would require changing RVE orchestration, finalization, publication, or source/NAS semantics.

Report:

- exact blocker;
- affected file/path;
- current behavior;
- smallest safe architectural option.

Do not work around a blocker by weakening validation or forcing an ambiguous classification.
