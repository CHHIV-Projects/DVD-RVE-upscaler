# 1. Goal

Inspect the actual repository and target runtime and determine the smallest safe architecture for the **DVD RVE Upscaler / DVD Enhance Assistant**.

The intended finished product is a LAN browser application where the Product Owner can:

```text
select an original DVD MKV already on NAS
→ analyze the media
→ determine progressive/interlaced/ambiguous status
→ prepare the source when needed
→ run RVE TensorRT enhancement
→ encode through NVENC
→ monitor progress and temperatures
→ validate the finished candidate
→ publish a separate enhanced version to NAS
→ use Original and Enhanced as Jellyfin versions
```

Normal product operation should require as little CLI interaction as practical.

This milestone must determine how to implement that workflow safely using the actual installed software and current server environment.

## 5.4 Thermal finding

Manual testing showed:

```text
TensorRT + CPU libx264 final encode
→ CPU approximately 96–97°C sustained

TensorRT + NVIDIA NVENC final encode
→ CPU approximately 87–88°C sustained
→ occasional observed peaks around 91°C
```

Therefore GPU-first preparation and final encoding are current product requirements unless later evidence supports changing them.

Do not deliberately rerun the known high-temperature CPU `libx264` workflow during reconnaissance.

## 5.5 Interlace/progressive finding

Do not infer deinterlacing solely from `ffprobe field_order`.

Manual testing established that a DVD can report an interlaced field-order flag while actual frame-content analysis indicates progressive material.

Future analysis should be able to distinguish at least:

```text
progressive
interlaced_tff
interlaced_bff
telecine_suspected
ambiguous
unsupported
```

Ambiguous material must stop for review rather than silently receiving a destructive transform.

## 5.6 Original-media rule

Original DVD MKV files are immutable from this application's perspective.

Never:

```text
overwrite
rewrite
rename automatically
truncate
delete
repair in place
```

The enhanced movie is a separate version.

Example final naming concept:

```text
Movie Name (Year) - DVD Original.mkv
Movie Name (Year) - DVD RVE Medium 2x.mkv
```

## 6.12 Aspect-Ratio / Geometry Handling

```text

853:720

display:
approximately 16:9

854×480

```

The application must also anticipate other common DVD geometries, including 4:3 material.

Recommend a deterministic geometry policy using observed:

- coded width/height;
- SAR;
- DAR;
- appropriate even-dimension rounding;
- square-pixel target.

The policy should preserve intended display shape without unnecessary enlargement before RVE.
