## Manual Runtime Validation

LAN validation was performed using the already-approved development bind.

Observed private LAN IPv4 of `henderson-server1`:

```text
ip -4 addr show scope global
inet 192.168.1.173/24 metric 100 brd 192.168.1.255 scope global dynamic eno1
```

Temporary dev process started with the approved bind:

```bash
cd /home/chuck/projects/DVD-RVE-upscaler
. .venv/bin/activate
uvicorn app.main:app --host 0.0.0.0 --port 8010
```

Server-side validation succeeded:

```bash
curl -sS http://192.168.1.173:8010/
curl -sS http://192.168.1.173:8010/health
```

Observed results:

- root page returned HTML successfully;
- `/health` returned `{"status":"ok"}`.

Product Owner Windows-browser validation was then attempted at:

```text
http://192.168.1.173:8010/
http://192.168.1.173:8010/health
```

Initial browser access was blocked even though server-side validation showed the app was listening on `0.0.0.0:8010` and the LAN IP was responding successfully from the server. Read-only UFW inspection showed no existing rule for TCP 8010. After the Product Owner explicitly authorized the narrow LAN-only firewall change:

```bash
sudo ufw allow from 192.168.1.0/24 to any port 8010 proto tcp comment 'DVD RVE Upscaler LAN'
```

the Windows browser validation succeeded:

- `http://192.168.1.173:8010/` worked successfully;
- `http://192.168.1.173:8010/health` worked successfully;
- `/health` returned the expected `{"status":"ok"}` response.

Product Owner Windows-browser validation: PASSED.
